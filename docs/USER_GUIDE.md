# User guide

1. Follow README setup. Provision an **operator** and a different **reviewer** locally. Optionally provision an admin for organizational oversight. The admin is not a hidden superuser who can bypass review; it can read/edit organizational clips but approval requires a different reviewer account.
2. Sign in at `http://127.0.0.1:8891`. For a first exercise choose Flood-response assessment and **Create synthetic clip**. The colored moving patch and mock plate are synthetic privacy targets. Inspection and training offer alternate backgrounds; none is real footage or a statement about an agency's operations.
3. For your own authorized clip, enter a short title, lawful/authorized purpose and retention (1–30 days), then select a supported MP4. Do not upload footage you lack authority to process. The service does not independently establish consent, ownership or applicable legal requirements. Unsupported video fails with no published output. Exporting a compatible short clip elsewhere does not make its collection/sharing lawful.
4. **Restricted, unredacted preview** is private, freshly re-encoded review media. Original audio/tags are not in that preview, but visible identities remain. The original file is retained privately on disk and never has a raw HTTP route.
5. Scrub using video controls or the frame slider. Frame zero is the first decoded frame, not source wall-clock time. Browser seeks are presentation aids; server processing uses exact decoded frame indices. Add masks with normalized X/Y/width/height in `[0,1]`, with X/Y at the top-left and width/height positive. `first` and `last` are inclusive. A static region must enclose all movement during its interval; use multiple time windows/boxes if needed. Solid fill is intentionally conservative. Orange outlines are **drafts only** and do not alter pixels.
6. For the synthetic flood case, the default box `(0.06,0.15,0.24,0.18)` covers the entire moving patch through frames 0–39. Add a second box `(0.62,0.67,0.18,0.13)` for the mock plate through frames 0–39. These coordinates are known synthetic geometry, not learned detections or real-person labels. Maximum 32 masks.
7. Enter private notes/annotations. Optional telemetry is a JSON list of `{ms, east_m, north_m, altitude_m}` using relative local coordinates and increasing unique timestamps. Offset is added to telemetry time to align with video. First/last sample should cover first/last frame within 250 ms; adjacent samples must be <=1000 ms apart. Missing telemetry is explicitly unknown; supplied drift/gap warnings must be resolved before approval. The synthetic telemetry button is an example, not a real flight record.
8. **Process new revision** rebuilds from the original, saves hashes/plan, then defaults the viewer to **Processed revision**. Inspect the actual output, not orange outlines. Up to five revisions per clip; at most 12 retained clips. The processed video has no source audio. Check visible identifiers, context, reflections and frame boundaries. All masks/revision details remain private; a sparse region can miss identifiers.
9. Sign out, sign in as the independent reviewer, select the clip, inspect the full processed video and compare the restricted preview where necessary. Confirm full-clip and context review, then record a descriptive approval or rejection. The application records an attestation; it cannot prove a reviewer actually watched carefully. It does not authorize a flight or make legal decisions.
10. Only the current approved revision exposes **Download reviewed MP4** and **Download minimal receipt**. The receipt is deliberately sparse. Review it and the MP4 before sharing through an authorized channel. No public share link is created. Source hash, original title/name, authorizing purpose, account names, notes, masks and telemetry are not in the receipt. The application author attribution is public, not the reviewer identity.
11. Any new processed revision invalidates earlier approval. Rejection is final for that revision; an operator must create a new revision for further review. The current revision/version query is enforced on media requests so a stale tab cannot silently download a different revision.
12. **Show access & revision history** lists media/state events and revision hashes for this clip only. Expired clips disappear from the library and return an explicit retention lockout. Purging expired local originals is an OS-owner task described in the operations guide, not automatic secure erasure.

## Help and errors

If continuous video cannot play, the UI automatically selects frame-by-frame mode after an error/short loading deadline. You can select **Use frame-by-frame review** on any browser. Move the frame slider then press **Load selected frame**. This is a real server-decoded PNG of the authorized preview/revision, not an illustrative placeholder. Wait for it to finish before another heavy job; a single-worker backpressure limit protects the application. No persistent PNG cache is stored. Check every relevant frame, not just frame zero. These controls do not prevent a permitted reader from saving or screen-capturing private preview pixels; this is a trusted review workflow, not DRM.

- `401`: session expired/revoked; sign in again. `403`: wrong role, CSRF or origin, or attempted self-review. `404`: missing/inaccessible object (not permission to enumerate others).
- `409`: stale version, missing review, unresolved attestation/timeline, revision/clip capacity. Refresh; do not assume an earlier approval applies. Resolve telemetry or intentionally omit unavailable position samples rather than invent measurements.
- `410`: retention expired. Do not bypass by changing the database; follow organizational retention/hold rules.
- `413/415/422`: body too large, wrong media type, unsupported/damaged video, invalid geometry/timestamps or native verification failure. No partial output is published. Use a controlled fixture to distinguish format problems from a broken environment.
- `429`: sign-in/body/processor backpressure. Wait for the active local job or login window; changing usernames is not a bypass.
- `503/507`: integrity/storage failure or insufficient space. Stop and investigate privately; do not remove hashes/review gates. See operations guide.
- Video cannot play: the browser/OS needs H.264 support. Use a supported up-to-date browser. Native worker success alone does not establish browser codec availability.
