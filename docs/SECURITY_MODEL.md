# Security and privacy model

## Intended environment

One organization, one loopback-bound process, trusted OS and provisioned staff, short authorized clips. No public internet hosting or adversarial multi-tenant upload service is supported. This application does not recognize identities, track people between clips, fetch remote media, call model APIs, control aircraft or make legal sharing decisions.

Assets: original bytes/audio/metadata, unredacted review previews, account hashes/session bearers, private purpose/notes/telemetry, processed video and review decisions. Runtime must be on a private encrypted OS volume, outside cloud-sync/public web folders. Do not put `.runtime` or its backups in Git. The repository contains no real footage or production accounts.

## Threat/control matrix

| Threat | Implemented control | Residual boundary |
| --- | --- | --- |
| Unauthenticated browsing / password guessing | CLI-only provisioning, Argon2id 64 MiB / 3 passes / parallelism 1; generic failures; 20 attempts/direct client/minute; <=2 concurrent expensive verifications; <=1000 active client rows | Shared loopback throttle can be denied by another local process. No MFA or public reset/recovery flow. |
| Session theft/fixation / stale role | Fresh opaque random token, only SHA-256 stored, separate CSRF token, HttpOnly/SameSite Strict cookie, one-hour absolute expiry, <=10 sessions/user, role re-read per request, immediate logout revocation | Local HTTP has no Secure cookie; loopback only. OS malware/admin/browser extensions are outside the trust boundary. |
| DNS rebinding / CSRF / cross-site input | Exact `127.0.0.1:port` Host, exact POST Origin, reject cross-site fetch, session CSRF on all other writes, no CORS; `proxy_headers=False` | Do not change binding/proxy behavior without a new security design and HTTPS/Secure cookies. |
| Other user's clip / ID enumeration | Server-side operator ownership before details, reviewers/admins are intentional organizational readers; opaque IDs; 404 inaccessible object; expiry on every API media/metadata/history/receipt read | This is organizational RBAC, not tenant isolation or client-side encryption. The computer owner can read/modify data. |
| Arbitrary path / SSRF / malicious filenames | Raw bounded upload, generated UUID filenames, fixed browser endpoints, `BytesIO` + forced MOV demuxer, protocol allowlist, external MOV references disabled, no uploaded filename retained, private non-static media root, path/symlink checks | Native parsers are not memory-safe. A subprocess is not an OS network/memory sandbox. Never accept public hostile uploads. |
| Native crash / resource exhaustion | Short input/pixel/frame/byte caps; continuous integer-rate PTS; reject dimension changes/corruption; one native worker, 90-second kill/wait deadline; two body readers and request deadlines; thread counts 1; clip/revision limits; >=256 MiB free-space precheck; failed-job scratch cleanup | Native allocation can occur before all checks. No cross-platform hard RSS quota. Large/devious files can still crash/exhaust the trusted local session. Revalidate vendor updates; deploy untrusted parsing in OS isolation if expanding scope. |
| Output metadata/audio leakage | New RGB frames and video stream; no remux of source side streams, frame side data, tags or names; decode verification of output stream/tag allowlists; minimal receipt omits source hash, title, user, notes, masks and telemetry | Technical encoder/MP4 tags remain. Pixel content and camera characteristics can be identifying. Raw originals still contain original data until purge. |
| Missed redaction / edge bleed | Outward-rounded solid masks with eight-pixel margin, inclusive frame intervals, independently decoded requested regions <=24/255; separate human full-clip/context attestation | No detector. Boxes/time intervals can be wrong. Verification does not find identifiers outside masks. No promise of anonymity, photogrammetric privacy or legal compliance. |
| Stale approval / concurrent edits / tampering | Immutable SQL revisions/reviews, source and plan/media hashes, CAS, exact media version query, independent reviewer, approval bound only to current version; reject drift, expiry, failed hash or incomplete work | Hashes are unsigned and the OS owner can alter files/DB. Not certified forensic chain of custody. A reviewer can falsely attest. A transfer already authorized/in flight or downloaded cannot be recalled. |
| XSS / clickjacking / injected ads | `textContent` for private text; self-only script/style/connect/media CSP; no third-party embeds/ads/analytics; DENY/frame-ancestors; nosniff/no-referrer/no-store; no inline execution | CSP cannot block a hostile browser extension, compromised OS or dependency. No arbitrary ad-blocker claim. |
| Retention / unintended purge | Per-clip immutable deadline; expiry lockout; OS-owner dry-run-first explicit purge validates all generated clip directories/files before deletion; audit remains | Not secure erasure. Backups, browser buffers, SSD remapping, swap and previous downloads need independent retention handling. Audit/account state is not automatically deleted. |

## Data handling and access history

The app collects only local usernames/password hashes, sessions, authorized clip data and review records. No telemetry is sent to the author. Media preview/redacted/export requests (including ranges) and state changes enter clip-scoped audit records with time, actor, event and version; this is not a full OS audit trail or a record of every viewed frame. History returns at most 100 events; retained rows remain on disk. No passwords, tokens, raw HTTP bodies or original filenames are logged. Uvicorn access logging is disabled.

The UI clears private selection/media sources on logout and rejects late responses using an authentication/selection generation counter. API authorization remains independent of UI state. Browser memory or a file already downloaded cannot be made unread by server revocation; close the session on a shared device.

## Release hygiene

Approval is an application workflow boundary, not DRM. An authorized reader can save/screen-capture a private preview or already received derivative. The designated export route is blocked until review, but a server cannot revoke bytes already disclosed to a permitted reader. Codec-independent frame rendering uses only hash-checked sanitized preview/current derivative, with the same ownership/version/expiry checks and a second version check after native decoding; no PNG cache persists. It does not expose raw originals or widen reader roles.

Python and npm have exact versions/integrity locks; Python installs vendor wheels only. Required live advisory checks fail on findings/unavailable/incomplete results, with no advisory suppressions. Complete npm inventory is independently verified. Native FFmpeg versions are printed by the benchmark; pip/npm advisory scans do **not** prove that every bundled FFmpeg/codec component is free of CVEs. Review [FFmpeg security](https://ffmpeg.org/security.html), wheel provenance and vendor notices before upgrades or real sensitive use. CodeQL covers Python and TypeScript, not a full native FFmpeg audit.

Tests cover cross-user access, CSRF/origin/Host, real TCP spoofed proxy headers, retention, tampering, output pixels/streams/markers, interrupted jobs, CAS/review races and late-response logout. No external penetration test or production certification has been performed. Report a private vulnerability through the contact route in [SECURITY.md](../SECURITY.md); never attach real footage, passwords or session tokens.
